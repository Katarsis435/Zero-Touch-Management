## Слайд 2. Актуальность
Сети 5G и 6G — это сложные платформы с сетевыми срезами, облачными функциями и миллионами устройств. Управлять этим вручную — медленно и опасно. Ошибка в CLI может отключить тысячи абонентов.
Решение — Zero-Touch Management: человек задаёт цель, система делает всё сама.
Но есть проблема: давая системе права, мы расширяем поверхность атаки. Безопасность становится критичной.

## Слайд 3. Проблемы безопасности
Основные угрозы: подмена телеметрии, атаки на ML-модели, утечка секретных данных (K, OP/OPc), галлюцинации LLM и отсутствие объяснимости.
Вывод: без верификации и локального выполнения автоматизация небезопасна.

## Слайд 4. Два подхода
Я сравнила два подхода: MARL и LLM.
MARL — хорош для оптимизации в реальном времени, но требует данных и плохо объясним.
LLM — генерирует конфигурации с нуля, работает быстро и локально.
Вывод: их можно сочетать.

## Слайд 5. LLM-NetCFG
Рассмотрела систему LLM-NetCFG: пользователь даёт интент на естественном языке, LLM генерирует команды, Batfish проверяет.
Точность — 92.2%, время — 5–10 минут.
Проблемы: 7.8% ошибок и долгое время реакции. Система не готова для реальной сети.

## Слайд 6. Мой эксперимент
Проверила генерацию на локальном оборудовании: Windows 10, Ollama, phi3:mini, Python.
Запрос на русском — модель сгенерировала YAML-конфиг и команды.
Вывод: работает, но без верификатора ошибки остаются. Нужен Batfish.

## Слайд 7. Заключение
Выводы: LLM генерирует конфигурации и решает проблему приватности. Но без верификатора — небезопасно. 10 минут — слишком долго. MARL требует огромных ресурсов.
Итог: ни LLM, ни MARL не готовы к промышленному применению. Нужен гибридный подход: LLM генерирует черновик, человек или верификатор проверяет.
